Архитектура:
UI и Контроллер

  • Console (View): Отдельный слой UI.
  • GameManager: Контроллер системы. Единая точка входа, которая принимает команды от Console, передает их в модель и возвращает ответ для отрисовки.
  • Game: Внутренний контроллер партии (Машина состояний). Обеспечивает валидацию действий игроков согласно правилам.

Архитектура:
Движки и Сервисы

  • Engines (My/Enemy): Отвечают за правильный переход к действию, проверяя корректность переданного от пользователя хода.
  • Attack: Сервис, работающий с истинным состоянием доски. Наносит удары и изменяет статусы клеток.
  • Scan: Принимает центр координат, обрисовывает зону радара и возвращает список.
  • ShipPlacement: Устанавливает корабли на сетку и строго отслеживает лимиты доступных типов судов.

Доменная Модель

Board

Управляет сеткой координат, обновляет статусы, мониторит поражение и самостоятельно инициализируется.

Player

Хранит имя пользователя, привязанные доски и проверяет количество оставшихся спец-предметов.

Ship & Types

Полиморфные классы. Хранят состояние своих клеток и метод isSunk() для проверки потопления.

Coordinate

Технический класс для парсинга. Вычисляет расстояние между точками по метрике Чебышева.

Работа с БД

  • History Repository: Предназначен для транзакционной записи ходов в базу и извлечения данных для системы реплеев.
  • Statistics Repository: Выполняет агрегирующие запросы для получения статистики по конкретным игрокам и рейтингам.
